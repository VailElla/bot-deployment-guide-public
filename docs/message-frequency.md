# 消息频率、冷却与投递预算

以下是本项目维护源码的示例策略，并非 QQ 或 AstrBot 的官方默认值。可用代码和安装方法见 [消息频率限制组件](../components/message_limits/README.md)。该插件独立运行；不要与原本机 Codex 桥接的同类钩子或旧私聊限频插件叠加启用。下面的计数与结果按当前整理的实现说明，不表示真实平台已经验收。

## 策略和实现位置

| 范围 | 策略 | 代码与边界 |
| --- | --- | --- |
| 私聊入站 | 同平台实例、Bot 账号、发送者，滚动 600 秒最多 30 条；超出静默，不延长窗口。群聊不计入。 | `private_limit.py`；SQLite 跨重载保留。仅 OneBot 好友消息；自己的消息和缺少可信身份不计次。 |
| 群触发 | 同平台、账号、群、发送者，滚动 120 秒最多 3 次；同平台、账号、群合计最多 6 次。超限静默，不重置和延长已有计数，过期逐条释放。 | `loop_guard.py`；计的是已准入的回复请求，不是发出的消息数。有效显式唤醒、续聊及随机请求都应经过此检查。 |
| 防重复与循环 | 相同发送者、群和内容的请求 300 秒内重复静默；忽略引用信封 ID，规范化文本的空格与大小写。自己发出的群消息不触发。 | `loop_guard.py`；附件等非文本组件参与签名。仅适用于可见的事件，并非内容审核或平台消息 ID 去重。 |
| 成功后的单次续聊 | 明确唤醒并成功交付模型回复后，同平台、群、发送者 60 秒内可免再次唤醒接话一次；在接纳时消耗，失败也不恢复。 | `group_followup.py`；要求新的文字消息；指向他人、全体或命令等不会消耗正常接话。普通随机插话和续聊不会开启新窗口。 |
| 随机插话 | 群级 300 秒冷却；选中前再次检查，在入队前占位，成功发送后再计时。直接 @ Bot 时重置该群冷却；明确请求不等待此冷却。 | `group_followup.py`、`proactive_guard.py`；还受 `loop_guard.py` 的 120 秒安静期及群／个人计数约束。`disable_random_groups` 可按群关闭。概率由 AstrBot 的随机回复设置决定，本插件不设概率。 |
| 入群欢迎 | 同平台、Bot、群 120 秒最多接纳一次入群事件；失败也占用窗口，重复处理同一个内存事件不延长。 | `join_welcome.py`；SQLite 持久化，插件只放行或阻止事件，不提供欢迎文本或生成逻辑。 |
| 群回复发送 | 按 Bot 账号和群，每滚动 60 秒至多 5 个回复轮次，完整一轮的多条发送共用名额；没有可识别事件归属的发送保守按次计算。额度不足时可取消地等待。 | `group_delivery.py`；明确 QQ 群限额拒绝后该群等待 61 秒，同一事件后续发送不再继续；不自动重发失败内容。实际 QQ 可能按消息条数计数，因此依然可能拒发。 |
| 文本分段节奏 | 平台实例 ID 为 `snowluma` 的模型纯文本首段不延时，后续段之间随机 0.4–0.8 秒；其他场景沿用框架。 | `reply_pacing.py`；这是间隔策略，不是平台配额。可用 `reply_pacing=false` 关闭。 |
| 故障通知 | 同类别 600 秒冷却，跨类别至少相隔 30 秒；冷却期内聚合。容量不足静默，但正文或语音拒发应识别为交付失败。 | `incident_aggregation.py`；本仓库提供聚合类和测试，默认**未接线**至日志或 QQ，需另行集成。失败后的重试等待 30 秒，必须确认回执。 |
| 表情包节奏 | 原设计参考每三次完整回复搭配一次，实际取决于语境与用户要求，明确要求配图可例外。 | 模型偏好，不是硬限额；需要单独的表情插件和合法素材，此组件不包含。 |

## 顺序与边界

1. OneBot 事件进入时先执行私聊和欢迎的入口限频；群事件经过唤醒和续聊判断，再预留群及发送者的回复请求名额。普通群友闲聊不消耗该请求名额。
2. 随机请求需要先通过群冷却及原生随机判断，再在异步返回后复查并预留，避免多个候选同时占用。@ 其他成员、@ 全体或只有昵称文字不重置 300 秒群冷却。
3. 生成后，平台实例 ID 为 `snowluma` 的普通非流式群聊按票据顺序投递；相邻轮次的模型生成与之前的交付可重叠。发送预算只覆盖经过该适配器的路径；插件直接调用底层 API、流式或后台消息不保证受同一限制。
4. 回复轮次预算与 QQ 的实际消息限额是两套计数。音频、文字、表情或转发可能是多次平台操作，即使本地只算一轮也可能被平台拒绝。不能用重新发送来掩盖状态未知或超时。

私聊与欢迎的 SQLite 事务可跨进程同步；群请求、续聊和随机状态在单个运行实例内同步预留并保存到文件，**不构成多进程分布式限流**。群文件状态只保存哈希及时间，但低熵标识仍可能被推测，应限制本机访问。发送预算保存在进程内，普通重载可复用；完整进程重启后无法获知 QQ 在重启前的实际计数。不要把插件重新加载视为真实接收端验证。

## 验收

用虚构账号分别测试第 3/4 次个人触发、第 6/7 次群触发和 120 秒边界；私聊第 30/31 次与 600 秒边界；同事件重入、重复内容、不同群与账号；续聊只使用一次；跨成员随机冷却、直接 @ 重置、禁用指定群；入群欢迎重启与数据库失败；一轮多段、五轮后的等待、明确 299、取消与重载。检查群正文拒发仍能进入实际告警接线。最后用授权测试账号和接收端核对真实行为。
