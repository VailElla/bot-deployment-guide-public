# GPT-SoVITS V5 Dev 中文单角色训练方案

本页根据一次中文单角色 V5 Dev 实验整理训练过程，补充[语音系统指南](voice-system.md)。它说明实际采用过的训练设计与关键检查，不是上游提供的完整一键流程。数据、代码、定制训练器、无参考推理适配、模型权重与音频均未在本仓库发布；读者需要先取得有权使用的素材，并自行实现、审查和验证相关代码。公开版本不包含私人台词、源文件、部署路径或最终声线检查点组合。

**能力边界：**V5 Dev 的声学模型与 GPT 语义模型是不同部分。官方 V5 少样本声学微调的支持状态需查[上游特性说明](https://github.com/RVC-Boss/GPT-SoVITS/wiki/GPT%E2%80%90SoVITS%E2%80%90features%28Latest%E2%80%90Including%E2%80%90v5%29)及实际代码。本实验的 CFM 全参数/LoRA 训练、共享角色向量和无参考输入路径均为定制研究实现，不应理解为官方 WebUI 默认可复现，也不保证适用于其他版本。

## 一、路线总览

```text
经授权的中文单角色录音
  ├─ 人工审核 → 按原始录音来源分组 → 训练集 / 验证集
  ├─ 音频和台词检查 → 音素、文本特征、语音语义及声学特征
  ├─ GPT 语义训练：从兼容的预训练 GPT 初始化 → 多个检查点
  └─ V5 Dev 声学训练：官方 V5 Dev 底模 + 训练集角色向量
       ├─ CFM LoRA（不同 rank）+ 角色向量
       └─ CFM 全参数 + 角色向量（其他模块冻结）
             ↓
  固定验证数据和噪声筛选 → 固定文案、多种子试听与内容检查
             ↓
  人工选定兼容组合 → 独立运行环境测试 → 按需部署
```

“CFM 全参数”在这里仅指**CFM 声学生成网络及共享角色向量**，并不表示整个 SoVITS、声码器或 GPT 都参与训练。GPT 阶段和声学阶段应分别记录起始权重、可训练参数与导出格式。

## 二、环境与可恢复性

1. 建立独立实验目录和 Python 环境，记录操作系统、显卡、驱动、CUDA、PyTorch、上游源码版本、预训练模型来源和许可证。官方底模与定制脚本固定版本，记录文件哈希；不要覆盖原有生产安装。
2. 预先检查显存、磁盘、训练与验证输入、输出目录和中断恢复空间。先短跑最长样本，观察显存峰值、实际优化器更新、非有限数值和检查点能否重新加载。
3. 把数据清单、参数快照、训练器源码版本、实际学习率、每轮样本数、损失与错误写入实验记录。Windows 可用无定时触发的一次性后台任务运行，必须检查任务状态并防止同一实验重复启动；远程连接断开不应被当作训练完成。
4. 区分**推理导出**与**完整训练状态**。续训状态需包括模型、优化器、混合精度 scaler、学习率调度器、更新计数和随机数状态；仅有推理权重不能保证按原轨迹恢复。先保存旧实验，再按最新完整状态恢复，避免覆盖已有检查点。

## 三、素材审核、分组与预处理

- 原始录音逐条确认说话人和使用授权，排除多人混入、非目标声线、不可辨识台词和无法确认来源的素材；疑似问题单独留审，不把机器标注当成人工审核。
- 保留原始录音，长录音可在自然停顿处分段；切点、时长和文本对应关系要可追溯到源。不要为凑时长而截掉有意义的字。若用转写和词级时间辅助切分，保留原台词和识别差异，复核专名、语气词、遗漏和边界；检查分段 PCM 是否与原始区间一致。
- **先按原始来源分训练与验证，再处理切片归属**：同一录音的不同切片不能分别进入两组。检查重复音频、相似台词和来源交集；角色向量初始化不得读取验证集。
- 如果为了长句保留整段版本、为声学训练另做按自然停顿切分的版本，应让两套清单都指向同一原始来源，记录切点、文本及实际训练分支。可以比较整段用于 GPT、分句用于声学训练的方案，但先检查各自加载器的长度和过滤条件，不保证整段一定优于分句。若部署者有意让验证素材与训练重叠，必须标记重叠及其范围：这种验证只能观察已见素材上的拟合，不能当作独立泛化评估；仍应尽可能保留按来源隔离的独立测试。
- 使用与实际 V5 Dev 版本匹配的文本前端、音素及 BERT 特征、HuBERT/语义编码和声学特征。检查每个被选样本所需特征齐全、非空且与音频及标注对应；数据或模型变化后不能盲用旧缓存。
- 验证 GPT 加载器的实际纳入数量及过滤原因。某些加载器会按音素与时长比例过滤，或在小验证集上复制样本以满足长度要求：报告**唯一录音数量**和实际评估次数，不把复制项当独立样本。

完成训练后的新一轮素材裁剪或重新分段属于下一版数据准备，不能追溯成已经训练了新清单。特征提取、加载器检查、人工听验和正式训练须分别标记完成状态。

## 四、GPT 语义模型训练

1. 从与所用 V5 Dev 流程兼容的预训练 GPT 权重开始，输入已经审核且实际通过加载器的训练集。验证集按来源隔离，保持固定。
2. 此次研究曾对两组学习率进行对照：峰值分别为 `1e-3` 和 `3e-4`，前 10% 更新 warmup，随后余弦下降到 `1e-5`；微批量 4、梯度累积 4、FP16，处理最后不足一个累积批次的更新。最多训练 40 轮，并定期保存及保留验证最佳候选。**这些是历史实验条件，不是推荐默认值或质量保证。**
3. 不只看配置文件：逐步记录优化器实际 `learning rate`。曾发现调度器将实际学习率固定，导致名义上的两组参数没有形成有效对照；修正训练器并验证真实曲线后，才将两组作为对照。这个检查也适用于梯度累积和优化器更新数。
4. 用同一验证集记录损失与准确度，并生成固定文案样音，检查漏字、拖长和重复。验证损失较低不等于听感更好。若继续训练没有改善，应停止并保留已有基线，而不是单纯增加轮数。

## 五、V5 Dev CFM 声学训练

声学阶段从官方 V5 Dev 声学底模初始化，不继承未经审核素材训练出的旧适配器；沿用架构配置不等于沿用旧权重。先从**训练集**的风格编码建立一个 512 维共享角色向量，并与声学模块共同优化，使同一角色可不依赖每次请求上传一段参考录音。

| 分支 | 训练范围 | 历史实验起始设置 |
| --- | --- | --- |
| LoRA 对照 | CFM 中的 LoRA，分别测试 rank 32 / 64，加共享角色向量 | 初始学习率 `1e-4` |
| CFM 全参数 | CFM 声学生成网络及共享角色向量 | 初始学习率 `1e-5` |
| 冻结部分 | 编码器、量化器、桥接网络、声码器及 GPT | 不参与此阶段更新 |

上述实验均使用 batch 1、FP16、梯度检查点和余弦学习率衰减至各自初值的十分之一，初次比较 12 轮，定期及按最佳验证结果导出。训练顺序一致，同一样本的噪声/时间采样使用配对种子；验证集每段使用多组固定噪声。检查可训练参数存在非零梯度、冻结权重哈希未变，且每轮实际覆盖预期样本。

FP16 的 GradScaler 可能出现溢出；不要把一次溢出直接当作样本已成功训练，也不要静默跳过。实验中降低 scale 后以同一噪声重试，记录溢出与实际更新。学习率、rank 和训练轮数均需依数据、实现和显卡重新试验；上述数字不是跨模型推荐。

### 全参数和 LoRA：如何制定对照

CFM 是声学模型中需要调整的部分，LoRA 是限制调整范围的一种方法。CFM 全参数训练让优化器更新所选 CFM 模块的全部参数；LoRA 冻结原有参数，只训练附加的低秩参数。二者在训练时都会由优化器自动更新模型数值，不需要人工逐个修改。两种路线也都可以同时训练共享角色向量。

全参数拥有更大的调整空间，但显存消耗和过拟合风险可能更高；LoRA 通常更省资源，也可能更好地保留底模能力。**训练成本越高不意味着音色一定更好**：素材质量、覆盖范围、训练设置和试听结果同样重要。

训练前应向部署者说明可选设置及其取舍，按资源和目标安排多个有记录的候选；不要把一个配置当成唯一答案：

| 要讨论和尝试的设置 | 关注点 |
| --- | --- |
| 学习率与调度 | 更新幅度和变化方式；分别检查实际学习率，过大可能不稳定，过小可能学习缓慢 |
| 训练轮数和检查点 | 定期保存多个候选；更多轮数可能过拟合，按验证和试听决定何时停止 |
| 训练范围 | 明确全参数是整个模型还是仅 CFM；对 LoRA 明确插入哪些层，以及角色向量是否训练 |
| LoRA rank | 决定附加低秩参数的容量；可比较多个 rank，较大不保证更好 |
| 批量大小与梯度累积 | 同时记录实际批量和有效批量；受显存限制时可比较合适设置，不能假定累积与大批量完全等价 |
| 显存和稳定性 | 比较混合精度、梯度检查点、梯度裁剪等设置，观察显存、溢出、实际更新及耗时 |

先用相同、按来源隔离的训练与验证素材建立全参数和 LoRA 基线，记录相同底模、输入预处理及各自可训练模块。各方法可以采用各自合理的学习率等设置；完整记录差异，不能把所有差别自动归因于方法本身。随后分阶段改变一项或少量设置，并保留基线和检查点，便于判断变化带来的影响；资源不足时先做小规模筛选，再扩展有希望的候选。

试听使用相同的留出文案、推理条件和多组配对种子，随机化顺序或隐藏方案名称。分别比较音色、内容完整度与自然度，同时记录漏字、重复、停顿和噪声；未听评项目标为未评。盲听及多种子能减少偏差，但不能证明所有场景都表现更好；验证损失和自动转写只作辅助筛选。

## 六、续训、验证与选择

可从完整声学检查点继续训练：先校验底模、输入和冻结参数指纹，恢复 AdamW、scaler、更新计数及随机状态；重新计算原检查点的固定验证结果，确认与原记录一致，再单独试跑最长样本。探测产生的更新不应混入正式训练。

一次历史续训从完整的 12 轮状态继续到总 48 轮，学习率由 `1e-6` 余弦下降到 `1e-7`，并设置每轮验证与早停。中断发生在尚未保存完整新一轮时，从最近完整状态重跑未保存部分；未来如已有更新的完整状态，应重新核对后使用该状态，不能重复运行旧入口。最佳验证检查点只是候选，最终选择还需人工试听；更多轮数也不保证改善。

比较声学检查点时固定 GPT、文案、随机种子及其他推理条件，并检查同一句的实际语义序列是否相同；比较 GPT 时固定声学模型。测试短句、长句、数字、名字、自然聊天和情绪变化，多种子盲听；语音转写可筛查漏字，但不能评价音色或替代人工听验。单次主观偏好应按原反馈记录，不扩大成所有场景均胜出。

## 七、无参考输入的定制推理

此实验的运行路径在合成时不读取参考音频：GPT 的参考提示为空，CFM 参考 Mel 帧长度为零，使用训练得到的共享角色向量；推理进程不加载参考编码器和 HuBERT。验证时应同时检查运行日志、输入路径与实际音频读取行为，不能仅凭界面隐藏上传框就宣称无参考。

这与“预先从某一段参考音频提取并缓存条件，之后不再读取音频文件”是不同方案；后者仍依赖参考派生条件。两者都不是证明上游所有 V5 Dev 模型支持无参考。

定制声学导出含 CFM 或 LoRA 参数及共享向量，仍依赖匹配的 V5 底模、架构与配套加载器；不能只改文件扩展名就导入任意官方 WebUI。部署前核对文件来源和哈希，先在独立进程合成，确认完整内容及听感，再接入 Bot 并保留旧版本回退。
